# Brief for the review site

Gustavo, 2026-09-20: "the html page you made is GOLD, we should produce one for each psalm. think of how we can have a whole unified thing where we can take a look at the psalms, word studies, and other artifacts you find useful. It's very useful as well to generate audit trail for reasons and justifications for choices."

Build **`research/psalterium/site.py`**: one command (`python3.13 research/psalterium/site.py`) that regenerates a static site into `research/psalterium/site/` from the data already on disk. No build tools, no dependencies beyond the standard library, pages open from `file://`. It must be safe to re-run all night as psalms arrive, and must not fail on a psalm folder that is half-written (skip it and list it on the index as incomplete).

## The design is already made — reuse it, do not redesign

`research/psalterium/review.html` is the approved look and behaviour: EB Garamond throughout, Cinzel only for section markers, Ember's parchment / ink / burgundy / gold palette with the dark-mode set, facing Latin | Portuguese columns with one colon per line and burgundy pointing marks, the sticky bar of typographic switches, dotted-gold open words that open a **popover in place** (bottom sheet on a phone) where choosing an option rewrites the verse, a gold wash where the choice departs from the draft, comparison psalters under each verse, notes per decision, localStorage, "Copy my decisions" → markdown. Lift its CSS and JS into shared `site/assets/site.css` and `site/assets/psalm.js`; generalise the JS to read its data from a `<script type="application/json">` block in each page instead of the hard-coded Ps 4 arrays. Known traps, already solved there — keep the solutions: no `lang="la"` on Latin (EB Garamond turns u into v); a decision can occur in several verses, so the popover anchors to the occurrence that was clicked; popover radios need their own `name` and a `data-decision` key; nested `<a>` is invalid; standing questions start unanswered.

No boxed cards, no pills, no generic borders, no entrance animations, no all-caps labels beyond the Cinzel markers, no monospace. Typographic hierarchy, fleurons (❦ ✠ ❧), space.

## Data

- `ps<NNN>/prayed.json` — schema in `AGENT-BRIEF.md`: `verses` with `{slot}`s, `decisions[]` (`id`, `refs`, `latin`, `kind`, `why`, `options[] {label, forms, note, from}`), `choices{}`, `audit[]`, `status`, `version`. `latin.py: resolve()` shows how slots fill (forms may nest). **`ps004/prayed.json` is the older schema** (flat strings, `choices`, no `decisions`); its decisions live hard-coded in `review.html`. Convert Ps 4 by writing `ps004/decisions.json` from review.html's `decisions` array and slot templates and teach `site.py` to merge it — do not edit `ps004/prayed.json` or `review.html`.
- Latin: `latin.py: readVerses(doLatin / 'Psalmorum/Psalm<N>.txt')`; `appPointing()` gives the app's pointing; the page offers both.
- `ps<NNN>/literal.json`, `checks.md`, `critic/*.json` (each has `role`, `model`, `at`, `prompt`, `reply` — the reply is a JSON string, sometimes fenced), `ps004/hard-readings.md`, `ps004/retrospective.md`, `ps<NNN>/decisions.md` where present.
- `words/<name>.md` + `<name>.concordance.md`, `glossary.md`, `PROGRESS.md`, `README.md`, `HANDOFF.md`, `collation/report.md`, `vos-tu.md`.
- Comparison psalters: copyrighted, so never embedded. A psalm page loads `../consult/compare/ps<NNN>.js` if it exists (`window.psalteriumCompare`, shape as in `consult/compare-ps004.js`) and hides the switch if it does not. Generalise `compare.py` to take a psalm number and write `consult/compare/ps<NNN>.js`: Douay-Rheims and the Hebrew-family CNBB / RSV2CE / KJV from Bolls (`parallels.py` has the fetch-and-cache helper and the Vulgate→Hebrew psalm-number map), Matos Soares 1932 from `parallels.py: matosSoares()` as one unsplit block shown once at the top of the psalm (its OCR cannot be split by verse reliably). Because verse division differs between the families, show a Hebrew-numbered version's verse under the Vulgate verse of the same number only when the psalm has the same verse count in both; otherwise show that version as a block at the top too. Never fill a missing verse from memory.

## Pages

1. **`index.html`** — the psalter at a glance: every psalm 1–150 plus the canticles present, with status (not started / draft / reviewed / unreviewed / decided), verse count, number of open decisions, version; grouped so that the pilot Hours (Sunday Compline: 4, 90, 133, Nunc dimittis; Sunday Prime: 53, 117, 118) stand first. Links to the glossary, word studies, method, and the decided questions.
2. **`ps<NNN>.html`** — the review page. Facing columns; switches for pointing, wording (draft / my choices), and what stands beside it (nothing / literal tier / other psalters); popover decisions; below the psalm, in this order: the decisions as a list (overview), **the audit trail** (the `audit` steps in order, each critic's verdict rendered readably — severity, the words, the problem, the fix, and whether it was taken, refused, or kept as an option — with model and date), the per-verse `choices` notes, the deterministic checks summary (hard result + flagged cola only), where the mouth stumbled (textarea), copy-my-decisions. Previous / next psalm links.
   **The layers view** (Gustavo: "it would be very nice as well if we could visually see the drafts / layers our methodology translate"). Each psalm page has a switch that turns the facing columns into the method's strata for every verse, top to bottom: Latin → interlinear gloss line (Ps 4 only: `ps004/interlinear.md`; skip where absent) → literal tier (`literal.json`) → each kept draft in order (`prayed.v1.json`, `prayed.v2.json`, …, then the current `prayed.json`, all flattened with `resolve()`) → the reader's own choices if they differ. Between one draft and the next, **mark what changed** (word-level diff: removed words struck through in muted ink, added words with the gold wash) and hang beside the change the critic remark or audit note that caused it (match by verse id against `critic/v<k>.*.json` and `audit[]`). Unchanged verses collapse to one line so the eye goes to what moved. This is the audit trail made visible: a reader should be able to see, for any verse, where it started, who objected, and what it became.
3. **`words/<name>.html`** — the study rendered from markdown, the concordance as a filterable table, links into the psalm pages at the verse (`ps016.html#v-16-1a`).
4. **`glossary.html`** — `glossary.md` rendered; each term links to its study if one exists and to the psalms whose `decisions` mention it.
5. **`method.html`** — README, HANDOFF, the Ps 4 retrospective, the collation report, the vós/tu record: the project's own audit trail.
6. **`decisions.html`** — every open decision across all psalms in one list, filterable by `kind` and by psalm, so a glossary-grade choice can be made once; and a second export that gathers all localStorage decisions from every psalm into one markdown.

A small markdown renderer is needed (headings, paragraphs, emphasis, code, links, tables, lists, blockquotes) — write one in Python rather than adding a dependency.
